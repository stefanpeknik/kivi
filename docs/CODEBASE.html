kivi — Codebase Reference

A deep-dive into every Rust concept, macro, crate, and design decision in kivi — a HashiCorp Vault KVv2 CLI written in Rust.

Architecture Overview

kivi has three clear layers with one-way dependencies:

CLI layer (src/cli/) — parses arguments, handles flags, calls the business layer
 ↓ calls
Business layer (src/editor.rs, src/completion.rs) — multi-step workflows
 ↓ calls
Vault API layer (src/vault/) — pure HTTP operations against the Vault API
 ↓ formats via
Output layer (src/output/) — human (ptree + comfy-table) or JSON

src/main.rs is the entry point. It resolves config + auth, constructs a VaultClient, then dispatches to the CLI layer. It knows about all layers but only to wire them — it contains no business logic itself.

Ownership & Borrowing

Rust's ownership system is the foundation. Every value has exactly one owner; when the owner goes out of scope, the value is dropped (memory freed). You can either move a value (transfer ownership) or borrow it (take a reference, &T or &mut T).

// Move: VaultClient is moved INTO the Arc, you can't use it after
let raw = VaultClient::new(...);       // raw: VaultClient
let client = Arc::new(raw);           // raw is moved; use client instead

// Borrow: the function gets a reference, caller keeps ownership
async fn read(client: &VaultClient, ...) { ... }
read(&client, ...).await;              // &client = borrow, client still owned here

The compiler enforces that you can't use a moved value, that borrows don't outlive their owner, and that you can't have a mutable borrow while any other borrow exists. This is what prevents data races and use-after-free at compile time — no runtime GC needed.

Arc — Shared Ownership Across Async Tasks

std::syncThread safety

Arc<T> (Atomically Reference Counted) allows multiple owners of the same value. Every Arc::clone increments an atomic counter; when the last clone is dropped, the counter hits zero and the value is freed.

let client = Arc::new(VaultClient::new(...));   // ref count = 1

// Spawn two concurrent tasks — each needs the client
let c1 = Arc::clone(&client);   // ref count = 2
let c2 = Arc::clone(&client);   // ref count = 3

set.spawn(async move { use_client(c1).await });  // moves c1 into task
set.spawn(async move { use_client(c2).await });  // moves c2 into task
// ref count drops to 1 when tasks finish; to 0 when client drops
Why not just pass &VaultClient to spawned tasks? Tokio requires spawned futures to be 'static — they must not hold references that could become dangling if the calling scope ends before the task. Arc<VaultClient> is 'static because it owns its data. A &VaultClient borrows from the caller's stack frame, which could be gone.

In kivi, commands that spawn concurrent tasks (list --long, tree, delete --recursive) take Arc<VaultClient>. Sequential commands take &VaultClient — a deref coercion automatically converts &Arc<VaultClient> → &VaultClient at call sites.

Result<T, E> and the ? Operator

Error handling

Rust has no exceptions. Fallible operations return Result<T, E> — either Ok(value) on success or Err(e) on failure.

pub async fn read(...) -> Result<SecretData, KiviError> {
    let raw = client.get(&api_path).await?;   // ? here
    let resp: KvReadResponse = serde_json::from_value(raw)?;  // ? here too
    Ok(SecretData { data: resp.data.data, ... })
}

The ? operator is syntactic sugar for:

match client.get(&api_path).await {
    Ok(v) => v,
    Err(e) => return Err(e.into()),   // .into() converts to the function's error type
}

The .into() matters — it allows automatic conversion from one error type to another if a From implementation exists. In error.rs:

#[error("HTTP error: {0}")]
Http(#[from] reqwest::Error),   // generates: impl From<reqwest::Error> for KiviError

So anywhere we ? a reqwest::Error inside a function returning Result<_, KiviError>, the conversion is automatic.

Async / Await and Tokio

tokioConcurrency

Rust's async fn syntax returns a Future — a value representing a computation that hasn't run yet. Futures are lazy: nothing executes until you .await them or spawn them onto an executor.

// This returns a Future immediately — no code in read() has run yet
let fut = kv::read(&client, mount, path, None);

// NOW it runs, suspending at each .await point if I/O is pending
let secret = fut.await?;

tokio is the async runtime — it runs futures on a thread pool. #[tokio::main] wraps main() to start the runtime:

#[tokio::main]
async fn main() {
    // this body runs inside a tokio runtime
}

This macro expands to roughly:

fn main() {
    tokio::runtime::Builder::new_multi_thread()
        .enable_all()
        .build()
        .unwrap()
        .block_on(async { /* your async main body */ });
}
Key insight: async fn functions return impl Future<Output = T>. Calling an async function doesn't execute it — it returns a future. Only .await (or spawn) actually runs it. This is why forgetting .await is a silent bug the compiler warns about.

JoinSet — tokio's way to run N futures concurrently and collect results:

let mut set: JoinSet<Result<(String, SecretData), KiviError>> = JoinSet::new();

for path in paths {
    let client = Arc::clone(&client);
    set.spawn(async move {              // spawn moves captured vars into the task
        let secret = kv::read(&client, mount, &path, None).await?;
        Ok((path, secret))
    });
}

while let Some(result) = set.join_next().await {   // collects one result at a time
    let (path, secret) = result??;   // outer ? = JoinError (task panicked), inner ? = KiviError
}

Pattern Matching

Exhaustiveness

Rust's match is exhaustive — the compiler rejects code that doesn't handle every case. This is load-bearing in kivi's dispatch in main.rs:

match &cli.command {
    Commands::Get(args)      => cli::get::run(args, ...).await?,
    Commands::List(args)     => cli::list::run(args, ...).await?,
    Commands::Tree(args)     => cli::tree::run(args, ...).await?,
    Commands::Put(args)      => cli::put::run(args, ...).await?,
    // ... every variant must be handled ...
    Commands::Config(_) | Commands::Completion(_) | Commands::Complete(_) => unreachable!(),
}

If you add a new command variant and forget to add it here, the code doesn't compile. No runtime "unhandled case" bugs.

if let is pattern matching for a single case:

// Only runs if cli.command is the Complete variant, binding args
if let Commands::Complete(args) = &cli.command { ... }

// Only runs if meta.deletion_time is Some, binding the inner value
if let Some(t) = &meta.deletion_time { println!("{t}"); }

impl Trait — Abstract Type Parameters

Generics 
pub fn new(
    address: impl Into<String>,
    token: impl Into<String>,
    namespace: Option<&str>,
) -> Self { ... }

impl Into<String> means "any type that can be converted into a String". This lets callers pass &str, String, or anything else implementing Into<String>. Without it, you'd have to write address: &str and force callers to pass string slices, or address: String and force them to allocate.

This is syntactic sugar for a generic type parameter: fn new<A: Into<String>, T: Into<String>>(address: A, token: T) — just more readable.

Lifetimes (Implicit)

Memory safety

Lifetimes appear explicitly only when the compiler can't figure them out. In kivi they're mostly hidden by lifetime elision rules. But they're real and enforced.

fn vault_args_for(cmd: &Commands) -> &VaultArgs {
//                     ^ borrow     ^ borrow returned
// Lifetime elision fills in: &'a Commands -> &'a VaultArgs
// The returned reference can't outlive the Commands it came from
}

The compiler enforces that you can't call vault_args_for(&cli.command) and then drop cli while still using the returned reference. If you tried, it would refuse to compile.

#[tokio::main]

proc-macrotokio

A procedural macro (proc-macro) that transforms the annotated async fn main() into a synchronous fn main() that starts a tokio runtime and runs the async body on it. Without this macro, you'd need to manually create and block on a runtime.

clap Derive Macros

proc-macroclap

clap's derive macros turn structs and enums into CLI parsers by reading attributes at compile time. No hand-written argument parsing code needed.

The three core derives

#[derive(Parser)]   // Top-level CLI struct — generates the main parser
pub struct Cli { ... }

#[derive(Subcommand)] // Enum of subcommands
pub enum Commands { ... }

#[derive(Args)]       // Argument group — can be reused across commands via flatten
pub struct VaultArgs { ... }

#[command(...)] — struct/variant attributes

#[command(name = "kivi", about = "HashiCorp Vault KV secret manager", version)]
pub struct Cli { ... }
// Generates: kivi --help shows "HashiCorp Vault KV secret manager", --version works

#[command(alias = "ls")]
List(list::ListArgs),
// Generates: `kivi ls` works as an alias for `kivi list`

#[command(hide = true)]
Complete(CompleteArgs),
// Hides this subcommand from --help output

#[arg(...)] — field attributes

#[arg(short = 'a', long, env = "VAULT_ADDR")]
pub address: Option<String>,
// short = 'a'      → -a flag
// long             → --address flag (derived from field name)
// env = "VAULT_ADDR" → also accepts $VAULT_ADDR environment variable
// Option<String>  → argument is optional; None if not provided

#[arg(long, env = "VAULT_TOKEN", hide_env_values = true)]
pub token: Option<String>,
// hide_env_values → VAULT_TOKEN value is shown as [VAULT_TOKEN] in --help, never the actual value

#[arg(value_enum, default_value = "human")]
pub output: OutputFormat,
// value_enum → generates tab-completion and validation from the enum's variants
// default_value → if flag not provided, use this

#[arg(long, required = true, value_delimiter = ',')]
pub versions: Vec<u64>,
// required = true    → must be provided (even though Vec could be empty)
// value_delimiter    → --versions 1,2,3 is parsed as vec![1, 2, 3]

#[command(flatten)] — composing argument groups

#[derive(Args)]
pub struct VaultArgs {
    pub address: Option<String>,
    pub token: Option<String>,
    pub mount: Option<String>,
    pub namespace: Option<String>,
}

#[derive(Args)]
pub struct GetArgs {
    pub path: String,
    #[command(flatten)]   // VaultArgs fields appear as if defined directly on GetArgs
    pub vault: VaultArgs,
}
// Result: `kivi get path/to/secret --address ... --token ... --mount ...`

Flattening is how kivi avoids global flags — each command owns exactly the flags it needs. config and completion have no VaultArgs flattened in, so they show no vault connection flags in their help.

serde Derive Macros

proc-macroserde 
#[derive(Deserialize, Serialize)]
#[serde(default)]
pub struct Config {
    pub address: String,
    pub mount: String,
    ...
}
  • Deserialize — generates code to parse TOML/JSON into this struct. serde::from_str::<Config>(toml_string) works.
  • Serialize — generates code to turn this struct into TOML/JSON. toml::to_string_pretty(&config) works.
  • #[serde(default)] — if a field is missing in the source data, use its Default::default() value instead of failing. This is what makes kivi's config forward-compatible: adding a new field with a default won't break existing config files.

For Vault API response types in vault/types.rs, only Deserialize is needed — we never serialize them back to JSON ourselves.

thiserror

proc-macrothiserror 
#[derive(thiserror::Error, Debug)]
pub enum KiviError {
    #[error("VAULT_TOKEN is not set...")]
    NoToken,

    #[error("Permission denied at path: {path}")]
    Forbidden { path: String },

    #[error("HTTP error: {0}")]
    Http(#[from] reqwest::Error),
}

#[derive(Error)] generates an impl std::error::Error for KiviError. The #[error("...")] attribute generates the Display implementation — what gets printed when you use {} on an error. Field references in the message string:

  • {path} → named field on the variant
  • {0} → first unnamed (tuple) field

#[from] generates impl From<reqwest::Error> for KiviError, enabling the ? operator to auto-convert reqwest::Error into KiviError::Http(...).

#[allow(...)] and Dead Code

lint attribute 
#[allow(dead_code)]
#[error("Vault mount '{mount}' is a KVv1 engine. kivi requires KVv2.")]
KvV1Engine { mount: String },

#[allow(dead_code)] suppresses the compiler warning that this variant is never constructed. It's kept because: (a) the error type is part of the public contract — callers should handle it even if kivi doesn't yet construct it, and (b) KVv1 detection will be added later. Documenting intent via the suppression attribute is better than deleting the variant and losing context.

The async runtime. Used features:

reqwest

reqwest 0.12

The HTTP client. Uses native-tls (OpenSSL on Linux) rather than rustls, so it picks up system CA certificates — crucial for corporate Vault deployments with internal CAs.

Key pattern — the custom LIST method that Vault's API requires:

self.client
    .request(Method::from_bytes(b"LIST").unwrap(), self.url(path))
    .header("X-Vault-Token", &self.token)
    .send()
    .await?

HTTP LIST is a custom verb not in the standard HTTP spec but used by Vault for directory listings. reqwest allows arbitrary method bytes via Method::from_bytes.

The PATCH content-type ordering matters:

.json(body)                                          // sets Content-Type: application/json
.header("Content-Type", "application/merge-patch+json")  // OVERRIDES it (insert replaces)

If you reversed these, .json() would overwrite the header and Vault would return HTTP 415.

serde 1

tempfile

tempfile 3

Creates temporary files that are automatically deleted when dropped. This is RAII (Resource Acquisition Is Initialization) — Rust's ownership system guarantees cleanup:

let tmp = tempfile::Builder::new()
    .prefix("kivi-edit-")
    .suffix(".json")
    .tempfile()?;         // creates /tmp/kivi-edit-XYZ.json

tokio::fs::write(tmp.path(), &content).await?;
// ... open editor, read back ...

// When `tmp` is dropped here (end of scope), the file is deleted automatically
// Even if the function returns early via ?, the drop still runs

The guarantee that cleanup runs even on early returns (via ?) is a key property of RAII — impossible to forget to delete the temp file.

VaultArgs Flattening

The initial design had Vault connection flags as global flags on the top-level Cli struct:

// OLD — global = true made them appear in every subcommand's --help
pub struct Cli {
    #[arg(short = 'a', long, env = "VAULT_ADDR", global = true)]
    pub address: Option<String>,
    ...
}

This caused kivi config set --help to show --address, --token, and --mount — flags irrelevant to config management. Worse, kivi config set -m apps was misinterpreted: -m was consumed as the global mount flag, leaving <KEY> and <VALUE> unset.

The fix: VaultArgs is a separate #[derive(Args)] struct that is #[command(flatten)]-ed into each vault command that needs it. config and completion don't flatten it in, so they're clean:

pub struct GetArgs {
    pub path: String,
    #[command(flatten)]
    pub vault: VaultArgs,     // Vault flags appear here
    #[command(flatten)]
    pub display: OutputArgs,  // --output, --no-color appear here
}

pub struct ConfigSetArgs {
    pub key: String,
    pub value: String,
    // No vault, no display — config set help shows only <KEY> <VALUE>
}

The vault_args_for / no_color_for Pattern

This is the code you highlighted. Since VaultArgs is embedded inside each command's args struct (not at the top level), main.rs needs a way to extract it regardless of which command was parsed. The Commands enum doesn't have a common trait with a vault_args() method — that would require Rust traits on enum variants, which don't exist.

The solution is a free function that matches on every variant:

fn vault_args_for(cmd: &Commands) -> &VaultArgs {
    match cmd {
        Commands::Get(a)       => &a.vault,
        Commands::List(a)      => &a.vault,
        Commands::Tree(a)      => &a.vault,
        // ... every vault command ...
        Commands::Metadata(a)  => match &a.command {   // nested subcommand
            MetadataCommand::Show(x)   => &x.vault,
            MetadataCommand::Set(x)    => &x.vault,
            MetadataCommand::Delete(x) => &x.vault,
        },
        Commands::Config(_) | Commands::Completion(_) => {
            unreachable!("called on non-vault command")
            // Can only reach this if the caller has a bug — safe to panic
        }
    }
}

no_color_for does the same for the --no-color flag, which lives on OutputArgs inside display commands (not on vault-only commands like put):

fn no_color_for(cmd: &Commands) -> bool {
    match cmd {
        Commands::Get(a) | Commands::List(a) | Commands::Tree(a) => a.display.no_color,
        // Metadata is special — only the Show subcommand has display args
        Commands::Metadata(a) => matches!(&a.command, MetadataCommand::Show(x) if x.display.no_color),
        _ => false,  // mutating commands don't have --no-color
    }
}
Alternative: implement a VaultCommand trait with a vault_args() method and have each Args struct implement it. This would be more extensible but adds a lot of boilerplate for a simple extraction. The match-based approach is explicit and the compiler enforces completeness when new commands are added.

Arc Asymmetry — Why Some Commands Take Arc, Others Take &

CommandParameterWhy
get, put, patch, edit, undelete, metadata&VaultClientSequential — one API call at a time. A borrow is sufficient.
list (with --long), tree, delete (--recursive)Arc<VaultClient>Spawns concurrent tokio tasks. Tasks need 'static data. Each task does Arc::clone(&client) to get its own handle.

At call sites in main.rs, client is always Arc<VaultClient>. Passing &client to a function expecting &VaultClient works via deref coercion: Arc<T> implements Deref<Target = T>, so &Arc<VaultClient> automatically coerces to &VaultClient.

JoinSet — Bounded Concurrent Fan-Out

The critical drain bug that the code review caught:

// WRONG — drain(..) removes ALL items; take(16) only consumes 16; rest are DROPPED
let batch: Vec<_> = dirs.drain(..).take(MAX_CONCURRENT).collect();

// CORRECT — drain only as many as you intend to process
let n = dirs.len().min(MAX_CONCURRENT);
let batch: Vec<_> = dirs.drain(..n).collect();

Why: Vec::drain(range) returns a Drain iterator that lazily yields elements. When .take(16) stops consuming after 16 items, the Drain is dropped. Drain's Drop implementation removes ALL unconsumed elements from the Vec. So any directory beyond the 16th sibling was silently discarded — leading to incomplete tree listings and missed recursive deletes.

editor.rs — Owning the Full Workflow

Initially, cli/edit.rs had two paths: --dry-run (opening editor, reading back, but not writing) and normal (delegating to editor::open_editor). This duplicated the "open temp file + invoke editor + read back" steps.

The fix: open_editor takes a dry_run: bool parameter and handles both paths internally. cli/edit.rs::run() becomes a single function call — the CLI adapter only parses args and calls the workflow once:

// cli/edit.rs — now just 35 lines
pub async fn run(args: &EditArgs, client: &VaultClient, mount: &str) -> Result<(), KiviError> {
    match crate::editor::open_editor(
        client, mount, &args.path, args.no_cas, args.diff, args.dry_run
    ).await? {
        Some(version) => println!("Written: {}/{} (version {})", mount, args.path, version),
        None => {}
    }
    Ok(())
}

KiviError — Typed Error Design

KiviError uses named-field struct variants for errors that carry context, and unit variants for errors that are self-explanatory:

NoToken,                              // unit — no context needed; message is self-contained
Forbidden { path: String },           // struct variant — which path triggered 403?
CasConflict { path: String, expected: u64 },  // two pieces of context
Http(#[from] reqwest::Error),         // tuple variant — wraps an external error type
TaskPanic(String),                    // tuple — task panicked, carrying the panic message

The benefit of specific variants over a generic string error: callers can match on KiviError::CasConflict and take specific action (the retry/force/abort loop in editor.rs), rather than parsing error strings.

Output — Dual Mode, Values Hidden by Default

Output format and value visibility are orthogonal — controlled by separate flags:

  • --output human (default) → ptree for trees, comfy-table for get, plain list for list
  • --output json → JSON via serde_json, same ValueMode applied
  • --show-values → reveal actual values in either format
  • --keys-only → omit values entirely in either format

The apply_value_mode function in output/mod.rs is the single source of truth:

pub fn apply_value_mode(data: &HashMap<String, Value>, mode: ValueMode) -> HashMap<String, Value> {
    match mode {
        ValueMode::Revealed  => data.clone(),
        ValueMode::Masked    => data.keys().map(|k| (k.clone(), Value::String("****".into()))).collect(),
        ValueMode::KeysOnly  => HashMap::new(),   // caller uses .keys() instead
    }
}

pub struct VaultClient {
    client: reqwest::Client,  // reqwest::Client is cheap to clone but expensive to create
    address: String,
    token: String,
}
// No pub on client — it's an implementation detail. Only VaultClient methods are public API.

impl VaultClient {
    pub fn new(address: impl Into<String>, token: impl Into<String>, namespace: Option<&str>) -> Self {
        let mut headers = reqwest::header::HeaderMap::new();
        if let Some(ns) = namespace {
            // Vault Enterprise namespace sent on every request via default headers
            headers.insert("X-Vault-Namespace", HeaderValue::from_str(ns).unwrap());
        }
        Self {
            client: Client::builder()
                .timeout(Duration::from_secs(30))  // hard timeout on every request
                .default_headers(headers)
                .build()
                .expect("failed to build HTTP client"),
                // expect() here is justified: building a client only fails on invalid config,
                // which is a programming error not a runtime condition
            ...
        }
    }

    fn url(&self, path: &str) -> String {
        format!("{}/v1/{}", self.address, path.trim_start_matches('/'))
        // trim_start_matches prevents double-slash: "https://vault/v1//apps/..."
    }

    pub async fn patch(&self, path: &str, body: &Value) -> Result<Value, KiviError> {
        self.client
            .patch(self.url(path))
            .header("X-Vault-Token", &self.token)
            .json(body)                                          // sets Content-Type: application/json
            .header("Content-Type", "application/merge-patch+json")  // overrides it (HeaderMap::insert replaces)
            .send().await?
        // Order matters: .json() last would overwrite our Content-Type
    }
}

// All KVv2 API paths follow a pattern:
// Read:          {mount}/data/{path}
// List:          {mount}/metadata/{path}  (LIST verb)
// Write:         {mount}/data/{path}      (POST with CAS option)
// Patch:         {mount}/data/{path}      (PATCH, merge-patch+json)
// Soft delete:   {mount}/data/{path}      (DELETE)
// Hard delete:   {mount}/delete/{path}    (POST with versions array)
// Undelete:      {mount}/undelete/{path}  (POST)
// Destroy:       {mount}/destroy/{path}   (POST)
// Metadata R:    {mount}/metadata/{path}  (GET)
// Metadata W:    {mount}/metadata/{path}  (POST)
// Metadata del:  {mount}/metadata/{path}  (DELETE)

pub async fn list_recursive(
    client: Arc<VaultClient>,   // Arc because we spawn tasks
    mount: &str,
    path: &str,
    max_depth: Option<usize>,
) -> Result<Vec<String>, KiviError> {
    let mut leaves = Vec::new();
    let mut queue: Vec<(String, usize)> = vec![(path.to_string(), 0)];

    while !queue.is_empty() {
        let n = queue.len().min(MAX_CONCURRENT);  // CORRECT bounded drain
        let batch: Vec<_> = queue.drain(..n).collect();

        let mut set: JoinSet<Result<(String, usize, Vec<String>), KiviError>> = JoinSet::new();
        for (dir, depth) in batch {
            let client = Arc::clone(&client);   // cheap atomic increment
            let mount = mount.to_string();       // move a clone into the async block
            set.spawn(async move {              // move captures vars by value
                let keys = list_keys(&client, &mount, &dir).await?;
                Ok((dir, depth, keys))
            });
        }

        while let Some(result) = set.join_next().await {
            let (dir, depth, keys) = result
                .map_err(|e| KiviError::TaskPanic(e.to_string()))??;
            //                ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^      ^^ = KiviError from list_keys
            //                outer ? = JoinError (task panicked), mapped to KiviError::TaskPanic
            ...
        }
    }
    leaves.sort();  // deterministic output regardless of task completion order
    Ok(leaves)
}

editor.rs walkthrough

pub async fn open_editor(
    client: &VaultClient,
    mount: &str,
    path: &str,
    no_cas: bool,
    show_diff: bool,
    dry_run: bool,
) -> Result<Option<u64>, KiviError> {
    // Returns Ok(Some(version)) = wrote successfully
    //         Ok(None) = no changes or aborted
    //         Err(e) = error

    loop {  // loop for the CAS retry case
        let secret = kv::read(client, mount, path, None).await?;
        let original_json = serde_json::to_string_pretty(&secret.data)?;
        let version = secret.metadata.version;  // capture version for CAS

        let tmp = tempfile::Builder::new()
            .suffix(".json")
            .tempfile()?;  // file deleted when tmp is dropped (even on early return)

        tokio::fs::write(tmp.path(), &original_json).await?;  // non-blocking write

        let status = tokio::process::Command::new(&editor)
            .arg(tmp.path())
            .status()      // returns when editor exits
            .await?;       // non-blocking: yields runtime thread while editor runs

        let edited = tokio::fs::read_to_string(tmp.path()).await?;

        if edited.trim() == original_json.trim() {
            return Ok(None);  // no changes
        }

        if dry_run {
            print_diff(&secret.data, &new_data);
            eprintln!("[dry-run] ...");
            return Ok(None);  // show but don't write
        }

        let cas = if no_cas { None } else { Some(version) };
        // CAS = Check-And-Set: Vault rejects the write if version != current_version
        // This prevents silently overwriting concurrent changes

        match kv::write(client, mount, path, new_data, cas).await {
            Ok(new_version) => return Ok(Some(new_version)),
            Err(KiviError::CasConflict { .. }) => {
                // Someone modified the secret between our read and write
                // Give user three choices: retry (re-fetch + re-edit), force, or abort
                let choice = Select::new()...interact()?;
                match choice {
                    0 => continue,  // jump to top of loop, re-fetches latest
                    1 => { kv::write(..., None).await?; ... }  // None = skip CAS
                    _ => return Ok(None),
                }
            }
            Err(e) => return Err(e),  // propagate any other error
        }
    }
}

completion.rs walkthrough

const COMPLETION_TIMEOUT: Duration = Duration::from_secs(10);

pub async fn complete(partial: &str, client: &VaultClient, mount: &str) -> Vec<String> {
    // Note: returns Vec, not Result — completion must never error or hang the shell
    let result = timeout(COMPLETION_TIMEOUT, do_complete(partial, client, mount)).await;
    match result {
        Ok(Ok(entries)) => entries,
        _ => vec![],    // timeout or Vault error → empty completions, shell continues normally
    }
}

async fn do_complete(partial: &str, client: &VaultClient, mount: &str) -> Result<Vec<String>, KiviError> {
    // Split "apps/team-a/ser" into parent="apps/team-a", prefix="ser"
    let (parent, prefix) = match partial.rfind('/') {
        Some(idx) => (&partial[..idx], &partial[idx + 1..]),
        None      => ("", partial),   // no slash = completing at root
    };

    let keys = kv::list_keys(client, mount, parent).await?;
    // e.g. ["infrastructure/", "rdu2/", "vault"] for the root

    Ok(keys.into_iter()
        .filter(|k| k.starts_with(prefix))   // only entries matching typed prefix
        .map(|k| if parent.is_empty() { k } else { format!("{parent}/{k}") })
        .collect())
    // dirs end with "/" — shell sees this and doesn't add a trailing space
    // leaves don't — shell adds a space, completing the argument
}
